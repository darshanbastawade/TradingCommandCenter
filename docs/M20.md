# M20 — Astra Backtest Analyst

M20 adds a constrained Azure OpenAI analyst for persisted M16 research evidence. The deterministic C# pipeline still owns every metric, rank, certificate and risk decision. Astra explains the supplied evidence, identifies weaknesses and proposes further tests; its recommendation cannot change qualification or authorize an order.

The integration uses the Responses API with the configured Azure deployment, `store: false`, no tools, low reasoning effort by default, and a strict JSON schema. GPT-6 Astra supports Responses and Structured Outputs according to the [official OpenAI model guidance](https://developers.openai.com/api/docs/guides/latest-model) and [Responses API reference](https://developers.openai.com/api/reference/cli/resources/responses/methods/create).

## Apply the migration

```powershell
dotnet run --project src/Trading.Api -- database-update
```

This creates `BacktestAnalyses`. Startup never changes schema. The SSMS alternative is [sql/M20-Astra-Backtest-Analyst.sql](sql/M20-Astra-Backtest-Analyst.sql).

## Configure Azure OpenAI

Keep the real values in User Secrets or environment variables. `Deployment` is the Azure deployment name whose deployed model should be GPT-6 Astra.

```powershell
dotnet user-secrets set "AzureOpenAI:Endpoint" "https://YOUR-RESOURCE.openai.azure.com" --project src/Trading.Api
dotnet user-secrets set "AzureOpenAI:Deployment" "YOUR-ASTRA-DEPLOYMENT" --project src/Trading.Api
dotnet user-secrets set "AzureOpenAI:ApiKey" "YOUR-KEY" --project src/Trading.Api
```

The committed non-secret defaults limit the research artifact to 750,000 characters, output to 4,000 tokens and the request to 120 seconds. The request does not enable web search, file search, code execution, functions or other tools.

## Run an analysis

Use a real persisted run ID from `GET /api/reports` and an output directory that already exists:

```powershell
dotnet run --project src/Trading.Api -- analyze-backtest `
  --research-run-id 00000000-0000-0000-0000-000000000000 `
  --output .\artifacts\astra-analysis-001.json
```

Before calling Azure, the command recomputes the stored research artifact SHA-256 and checks the run, dataset and configuration identity. It also checks SQL for an existing analysis with the same research run, prompt hash and deployment, preventing an accidental duplicate paid request. Existing output files are never overwritten.

The structured result contains an executive summary and exactly one analysis for every strategy in the research artifact. Each strategy receives evidence summary, strengths, weaknesses, robustness concerns, regime observations, execution concerns and one of `paperTest`, `moreResearch` or `reject`. It also contains portfolio observations, required next tests and warnings.

SQL and the JSON artifact record the provider response ID, requested deployment, returned model, prompt version/hash, research artifact hash, input/output token counts and final analysis SHA-256. `GET /api/analyses` lists metadata; `GET /api/analyses/{id}` returns exact stored JSON.

## Authority and trust boundary

Research JSON is explicitly treated as untrusted data, so strings embedded in imported evidence cannot become model instructions. The response must cover exactly the expected strategy IDs or the command rejects it. Astra may interpret supplied values but must not recalculate indicators, P&L, position sizes, rankings, qualification, certificates or risk.

`paperTest` is an analytical recommendation for controlled observation. It does not create an M19 certificate, bypass expiry, approve M18 risk, provide human approval or authorize live trading. M20 connects no broker and places no order.
