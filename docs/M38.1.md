# M38.1 — Mandatory M37 authorization for direct-live M23 submission

Every `live-order --mode direct` request now requires a verified, fresh M37 `ControlledAutomationArtifact` supplied with `--automation-authorization`. M37 still does not send an order. M23 remains the only component that invokes Zerodha.

The authorization must be schema v1, SHA-256 valid, `directSubmissionEligible`, unused by its own evidence (`brokerSubmissionPerformed: false`), limited to one action, and inside its UTC validity window. Its strategy must match the verified M19 certificate. Its action ID must equal the M23 request ID, and its action reference must exactly equal `automationActionReference` in the live intent. This binds M34 qualification, M35 paper qualification, M36 reconciliation, M37 decision, and the exact M23 request.

```powershell
dotnet run --project src/Trading.Api -- live-order `
  --mode direct `
  --certificate-id 00000000-0000-0000-0000-000000000000 `
  --file .\samples\live-entry.json `
  --automation-authorization .\artifacts\controlled-automation-decision.json `
  --output .\artifacts\direct-live-order.json `
  --confirm PLACE-LIVE-ORDER
```

Authorization verification happens before `ILiveBrokerClient` is resolved. The existing M23 configuration, operator confirmation, paper evidence, fresh account/quote, flat-account, zero-day-order, price and M18 risk gates remain mandatory. A new direct artifact uses schema v2 and records the automation decision ID/hash plus M34, M35 and M36 identities. Schema-v1 M23 artifacts remain readable and are not reinterpreted as M37-authorized.

Semi-live requires no M37 artifact and never calls the broker order-submission method. It still reads broker account and quote data to construct its proposal, as M23 already required.

M38.1 does not prevent replay of the same still-valid authorization. Durable one-time consumption is M38.2 and must be completed before unattended use.
