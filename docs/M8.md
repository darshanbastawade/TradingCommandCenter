# M8 — Chronological out-of-sample validation

M8 evaluates a selected strategy only on sessions later than those supplied for selection or parameter configuration. It adds a one-time chronological holdout and rolling or anchored walk-forward validation. Both paths reuse the deterministic M5–M7 backtest, costs, risk sizing and metrics.

## Selection boundary

`TrainingStrategySelector` receives an immutable list view containing only the current training candles and the exchange time zone. It returns an `ITradingStrategy` whose configuration is then frozen for that fold. The selected strategy evaluates prior context plus the test window so indicators can warm up, but `TestingWindowStrategy` admits candidates only when their signal session lies inside the test window.

The engine enforces the data boundary presented to the selector. The strategy implementation must still be causal: its signal at a timestamp must not change when future candles are appended. M4 has an explicit future-bar invariance fixture for the current strategy.

An embargo is an optional count of complete sessions between the end of training and the beginning of testing. Embargo candles are available as historical indicator context at test time, but they are excluded from selection, signals and performance metrics.

## Holdout

The holdout uses the first configured number of sessions for training, skips the embargo, and uses every remaining session once for testing.

```csharp
var result = TimeSeriesValidationEngine.RunHoldout(
    (trainingCandles, exchangeTimeZone) => SelectStrategy(trainingCandles, exchangeTimeZone),
    candles,
    exchangeTimeZone,
    new HoldoutValidationSettings(TrainingSessionCount: 500, EmbargoSessionCount: 5),
    backtestSettings);
```

Do not tune a strategy after inspecting this holdout and then describe another run on the same sessions as unseen. Repeated choices against one holdout turn it into training information.

## Walk-forward validation

Each walk-forward fold selects on prior sessions, skips the embargo and evaluates the next fixed-size test block. Test blocks never overlap and advance by `TestingSessionCount`.

- Rolling training retains exactly `TrainingSessionCount` sessions.
- Anchored training always starts at the first session and expands through later history.
- Only complete test blocks run. `UnusedTrailingSessionCount` reports a final partial block that was not scored.
- Earlier test sessions may become training data for a later fold, matching chronological re-selection with information available at that later time.

```csharp
var result = TimeSeriesValidationEngine.RunWalkForward(
    (trainingCandles, exchangeTimeZone) => SelectStrategy(trainingCandles, exchangeTimeZone),
    candles,
    exchangeTimeZone,
    new WalkForwardValidationSettings(
        TrainingSessionCount: 250,
        TestingSessionCount: 20,
        EmbargoSessionCount: 2,
        AnchoredTraining: false),
    backtestSettings);
```

Each `ValidationFold` records the precise session boundary, selected strategy ID, out-of-sample ledger and M7 metrics. Fold backtests start with the configured initial capital for comparability. The combined result orders all out-of-sample trades and recalculates `CapitalAfterTrade` from one initial balance, producing a continuous out-of-sample equity curve. It also reports profitable-fold count and rate.

## Interpretation and limitations

Chronological validation reduces look-ahead and selection leakage; it does not prove a profitable edge. Trying many configurations raises the chance of backtest overfitting, so the selector and number of trials must eventually be recorded. M8 does not yet rank strategies, calculate selection-adjusted significance, test parameter stability, run Monte Carlo paths or impose qualification thresholds.

Session boundaries assume the input contains the intended complete market sessions. The backtest still applies M5's end-of-data liquidation at the last candle in each test window. Missing end-of-session candles can therefore affect the final trade of a fold.

Method references: Bailey, Borwein, López de Prado and Zhu, [The Effects of Backtest Overfitting on Out-of-Sample Performance](https://papers.ssrn.com/sol3/papers.cfm?abstract_id=2308659); Robert Pardo, [Walk-Forward Analysis](https://onlinelibrary.wiley.com/doi/abs/10.1002/9781119196969.ch11); and scikit-learn's [time-series split with a configurable gap](https://scikit-learn.org/1.0/modules/generated/sklearn.model_selection.TimeSeriesSplit.html).

## Scope

M8 adds no database table, migration, package, Azure resource, AI call, broker connection or order path. Validation results remain research evidence and do not authorize a trade.

## Validation

```powershell
dotnet build TradingCommandCenter.sln --no-restore

```

Fixtures verify selector isolation, embargo exclusion, rolling and anchored windows, non-overlapping tests, incomplete-tail reporting, fold aggregation, chronological capital rebasing and invalid-input rejection.
