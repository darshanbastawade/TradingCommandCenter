# M19 — Strategy Certificate

M19 converts the selected output of an immutable M16 research run into a durable strategy certificate. It never reranks strategies and never manufactures a second selection: zero qualified selections produce zero certificates, while each selected strategy produces exactly one certificate.

## Apply the database migration

The local `Market` database needs `StrategyCertificates`:

```powershell
dotnet run --project src/Trading.Api -- database-update
```

Application startup never changes the database. The equivalent idempotent SSMS script is [sql/M19-Strategy-Certificates.sql](sql/M19-Strategy-Certificates.sql).

## Issue certificates

First obtain a persisted research run ID from `GET /api/reports`, then create an existing output directory and run from the repository root:

```powershell
dotnet run --project src/Trading.Api -- issue-certificates `
  --research-run-id 00000000-0000-0000-0000-000000000000 `
  --output-dir .\artifacts
```

Before issuance, the command recomputes the stored research artifact SHA-256 and checks its run, dataset and configuration identity against SQL. It accepts only strategies that appear in the artifact's selected ranking, remain marked qualified with no failure codes, and have a matching evidence section. Existing output files are never overwritten. The database uniqueness rule permits only one certificate for a research-run/strategy pair.

If the research run selected no strategy, the command succeeds with `no-qualified-strategies`, writes no files and inserts no rows. This is a valid research outcome.

## Certificate contents and lifecycle

Every schema-v1 certificate binds:

- certificate, strategy, policy and research-run identity;
- dataset, research configuration and exact research-artifact SHA-256 values;
- instrument, timeframe, tested date range and source revision;
- the complete M15 rank, score components and qualification result;
- tested risk, capital, lot, slippage and cost-profile constraints;
- issue and expiry timestamps;
- paper-trading eligibility, live-trading prohibition and human-approval requirement;
- a deterministic SHA-256 over the certificate payload.

Certificate IDs and hashes are reproducible for the same source and policy. The default validity period is 90 days from research-run creation, configured under `StrategyCertificates`. Expiry prevents stale research from being presented as currently valid; it does not alter the immutable stored artifact.

`GET /api/certificates` returns the catalog and calculates `isCurrentlyValid` at request time. `GET /api/certificates/{id}` returns the exact stored certificate JSON.

## Authority boundary

`ResearchQualified` means the strategy passed the declared M15 gates using the evidence in the linked M16 run. It is eligible to enter a separately controlled paper-trading stage. It is not proof of future profitability, human approval, a live-trading authorization, or an order instruction. M18 must still evaluate every proposed order, and later execution work must reconcile actual account state before invoking that gate.

M19 makes no Azure OpenAI call, connects no broker and submits no order.
