# M11 — Operational walk-forward engine

M11 makes the M8 walk-forward calculation operational against historical candles in SQL Server. It creates consecutive, non-overlapping out-of-sample folds and writes one versioned JSON artifact containing every fold report plus a combined out-of-sample report.

## Run from VS Code or PowerShell

Run this from the repository root, replacing the instrument ID and dates with registered data:

```powershell
dotnet run --project src/Trading.Api -- run-walk-forward `
  --instrument-id 00000000-0000-0000-0000-000000000000 `
  --timeframe 5 `
  --from 2025-01-01T00:00:00+05:30 `
  --to 2026-01-01T00:00:00+05:30 `
  --training-sessions 60 `
  --testing-sessions 20 `
  --embargo-sessions 1 `
  --training-mode rolling `
  --strategy-id opening-range-breakout-v1 `
  --initial-capital 100000 `
  --allowed-risk 750 `
  --maximum-capital 100000 `
  --maximum-lots 10 `
  --slippage-bps 5 `
  --cost-profile zerodha-nse-equity-intraday-2026-03-01 `
  --output artifacts/walk-forward.json
```

The output directory must already exist and the destination must be a new `.json` file. Timestamps require `Z` or an explicit UTC offset. Supported timeframes are the numeric `Timeframe` values used by the candle store.

`--strategy-id` accepts any ID in the M14 default catalog. It defaults to `vwap-ema-trend-breakout-v1` when omitted.

## Window rules

- `rolling` keeps the requested number of training sessions and advances it with each test window.
- `anchored` keeps the first training session fixed and expands the training history for later folds.
- The embargo is the requested number of sessions between training and testing. Those sessions appear in neither set.
- Test windows never overlap. Only complete test windows run.
- Sessions left after the final complete test window are reported as `unusedTrailingSessionCount` and are not scored.
- The training selector receives training candles only. The strategy may evaluate prior context for indicator warm-up, but the validation gate accepts trades only within that fold's test sessions.

## Artifact

The schema-versioned artifact records the training mode, source candle count, fold count, unused tail, profitable-fold count/rate, each fold's exact boundaries and report, and a chronologically stitched combined report. The combined ledger rebases realized P&L from the requested initial capital.

The current `vwap-ema-trend-breakout-v1` defaults are frozen for every fold; M11 does not optimize parameters. Each fold backtest starts with the configured capital for sizing, while the combined ledger rebases the resulting trades chronologically. Repeated experimentation on the same test folds can still cause research overfitting and must be tracked by the operator.

Supported cost profiles are `none`, `zerodha-nse-equity-intraday-2026-03-01`, and `zerodha-nse-equity-options-2026-04-01`. `none` is an explicit frictionless control.

M11 adds no database table, migration, package, Azure resource, AI call, broker connection or live execution path.
