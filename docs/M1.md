# M1 — Local persistence and market-data foundation

Current setup: SQL Server is installed and the project targets **DESKTOP-EF1NCS7 / Market**. Use [Market database setup](Market-setup.md). The LocalDB commands below describe the original optional setup.

M1 adds Instrument and Candle domain entities, an EF Core SQL Server DbContext, the initial migration and model snapshot, and an Application-level market-data store contract implemented by Infrastructure. Azure OpenAI remains configuration-only.

## Database setup in VS Code

The application still starts without a database. `/health` checks process liveness; `/health/ready` returns HTTP 503 until SQL Server is accessible and all migrations are applied. No migrations or data changes run automatically at startup.

SQL Server/LocalDB was not detected on the development machine during implementation. Install SQL Server Express LocalDB or use an existing SQL Server instance before applying the migration. See [Microsoft's LocalDB installation instructions](https://learn.microsoft.com/en-us/sql/database-engine/configure-windows/sql-server-express-localdb).

From the solution folder:

```powershell
dotnet tool restore
dotnet restore TradingCommandCenter.sln --locked-mode
dotnet build TradingCommandCenter.sln --no-restore
dotnet test TradingCommandCenter.sln --no-build
```

For LocalDB, after installation:

```powershell
SqlLocalDB start MSSQLLocalDB
dotnet ef database update --project src/Trading.Infrastructure --startup-project src/Trading.Infrastructure
dotnet run --project src/Trading.Api --launch-profile http
```

The development default is `Server=(localdb)\MSSQLLocalDB;Database=TradingCommandCenter;Trusted_Connection=True;TrustServerCertificate=True`. `TrustServerCertificate=True` is only intended for local development.

For another SQL Server, set the connection in the terminal before both migration and app startup:

```powershell
$env:ConnectionStrings__TradingDatabase = 'Server=YOUR-SERVER;Database=TradingCommandCenter;Integrated Security=True;Encrypt=True;TrustServerCertificate=True'
dotnet ef database update --project src/Trading.Infrastructure --startup-project src/Trading.Infrastructure
dotnet run --project src/Trading.Api --launch-profile http
```

The API also supports `ConnectionStrings:TradingDatabase` in User Secrets. The design-time factory reads the environment variable, otherwise the API appsettings.Development.json connection; it does not read API User Secrets. Use the same environment variable for both to avoid migrating a different database. Do not commit a credential-bearing connection string.

Open http://localhost:5080/health/ready and expect `Healthy` after setup. Responses never include the connection string or detailed database exceptions. Readiness checks connectivity, pending migrations and the existence of both tables.

## Schema and data rules

- Instrument IDs are application-owned GUIDs, independent of reusable broker tokens. Exchange and symbol are trimmed and uppercased; their combination is unique. Lot and tick sizes must be positive. No instrument master or current lot sizes are seeded.
- Candles have a composite primary key `(InstrumentId, Timeframe, OpenTimeUtc)`. It also supports time-ordered range queries for one instrument/timeframe. Foreign keys prevent orphan candles; deleting an instrument with candles is restricted.
- Incoming timestamps require DateTimeOffset, are converted to UTC, stored as `datetime2(7)`, and materialized with `DateTimeKind.Utc`. They identify the beginning of a completed bar. Session/calendar validation and bar alignment belong to the later importer. A Day1 timeframe means a daily bar, not a claim about exchange-session length.
- Prices and tick sizes use `decimal(18,4)`. More than four fractional digits are rejected before persistence. OHLC must be positive and within low/high; volume and optional open interest are nonnegative integers. Null open interest means unavailable, not zero.
- Supported timeframe values are 1, 3, 5, 15, 30, 60 and 1440 minutes. Domain validation and database check constraints reject unsupported values.
- Candle writes accept at most 10,000 bars and are atomic. A duplicate key rejects the batch; existing evidence is never silently overwritten. Dispose the request/DbContext scope after a failed write rather than reusing its pending tracked entities.
- Queries use a half-open UTC range `[from, to)`, ascending timestamp order, no tracking, and a maximum of 10,000 rows. For further pages, advance the start beyond the last returned timestamp without skipping any bars. Callers must consume all pages before a backtest.

## Migrations

The checked-in migration is `InitialMarketData`. Review the generated `docs/sql/M1.sql` before applying it. It is idempotent and checks migration history. EF CLI version 10.0.12 is pinned in `.config/dotnet-tools.json`.

```powershell
dotnet ef migrations has-pending-model-changes --project src/Trading.Infrastructure --startup-project src/Trading.Infrastructure
dotnet ef migrations script --idempotent --project src/Trading.Infrastructure --startup-project src/Trading.Infrastructure --output docs/sql/M1.sql
```

See [Microsoft's migration guidance](https://learn.microsoft.com/en-us/ef/core/managing-schemas/migrations/applying). Migration rollback drops these tables and their data; use forward migrations once real evidence has been stored.

## Verification boundaries and next milestone

The test suite covers domain validation, UTC conversion, relational roundtrips, ordering/limits, duplicate-batch rollback, uniqueness, foreign keys, SQL check constraints, and readiness without configuration. Fast relational tests use SQLite in memory; SQL Server migration generation and model-snapshot consistency are checked separately. SQLite tests do not prove SQL Server execution or full decimal precision behavior. A live SQL Server migration and readiness check remain necessary once the local instance is available.

M1 does not expose write endpoints or import historical data. The next milestone is a validated historical candle importer using this store. Strategies, indicators, trading execution, option-contract metadata and AI calls remain future work.
