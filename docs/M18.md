# M18 — Complete deterministic risk policy

M18 turns the agreed capital-preservation rules into one pure pre-trade decision. It accepts an explicit policy, immutable exchange calendar, point-in-time portfolio state, proposed entry/exit and price risk. It returns a whole-lot position size, every hard-gate failure, current period loss capacity and a SHA-256 decision fingerprint. It reads no clock, database, broker or AI service, so identical inputs produce an identical result.

## Default capital boundary

The committed `RiskPolicy` configuration exactly allocates ₹3,00,000:

| Pool | Amount | Deployable by the policy |
| --- | ---: | --- |
| Protected reserve | ₹1,50,000 | No |
| Active trading capital | ₹1,00,000 | Only for `Active` requests |
| Strategy testing capital | ₹30,000 | Only for `StrategyTesting` requests |
| Cash buffer | ₹20,000 | No |

Available account cash never expands either trading pool. Open capital in a pool reduces that pool's remaining capacity. The protected reserve and cash buffer cannot become recovery money after losses.

## Default hard gates

- maximum risk per trade: ₹750;
- maximum realized daily loss: ₹1,500;
- maximum realized Monday-to-Sunday weekly loss: ₹3,000;
- maximum calendar-month loss: ₹6,000;
- maximum aggregate open risk: ₹750;
- maximum three trades per exchange-local day;
- stop for the day after two consecutive losing trades;
- maximum one open position;
- only a qualified stable strategy ID may trade;
- scale-ins and any second position in the same instrument are treated as forbidden averaging;
- entries are allowed only in the intersection of the declared exchange session and the configured 09:15-inclusive/15:00-exclusive policy window;
- planned exits must be later on the same exchange-local date, no later than 15:25, and no later than that date's exchange-session close;
- a manual kill switch rejects every request;
- required capital cannot exceed free cash or the selected trading pool.

Daily, weekly and monthly limits use realized net P&L on exchange-local exit dates. If today's P&L is -₹1,000, the next request receives at most ₹500 risk. A profitable period cannot raise a trade above the fixed ₹750 cap. This prevents martingale or recovery sizing.

`EvaluateAndSize` first calculates the available risk and capital, then uses the M6 `PositionSizer` to round down by entry-to-stop risk and complete lots. If one lot cannot fit, the decision is denied; it never rounds up.

## Evaluate a decision from the CLI

Copy [../samples/risk-evaluation.json](../samples/risk-evaluation.json), replace the example identity, prices, qualification list and portfolio state, then run:

```powershell
dotnet run --project src/Trading.Api -- evaluate-risk --file .\samples\risk-evaluation.json
```

All timestamps must be UTC values ending in `Z`. `availableCash` means currently free, uncommitted buying power. `closedTrades` must contain only trades known before the proposed entry. Each open position records its capital pool. `capitalPool` accepts `Active` or `StrategyTesting`.

The result contains `approved`, calendar ID and SHA-256, the position size and lots, maximum currently approved risk/capital, daily trade and consecutive-loss counts, day/week/month P&L and remaining loss capacity, stable rejection codes, the low-level policy hash, and a final hash covering prices and the calculated size. The committed `ExchangeCalendar` configuration loads the same M16.1 calendar file used by research. Missing or invalid calendar evidence fails command preparation.

The active policy is visible at `GET /api/risk-policy`; `/api/status` identifies `deterministic-pre-trade-hard-gates-calendar-bound-v2`.

## Integration boundary

Research backtests remain free to evaluate unqualified strategies, because qualification is their output. M18 is the gate for a proposed paper or live order after a strategy has qualified. A later execution milestone must rebuild `RiskPortfolioState` from durable, reconciled fills and open positions and call `EvaluateAndSize` immediately before every order attempt.

M18 does not persist account state, connect to a broker, submit/cancel orders, infer whether a discretionary trade is revenge trading, or automatically disengage the kill switch. Those execution and operator-state responsibilities remain outside this deterministic calculation milestone.
