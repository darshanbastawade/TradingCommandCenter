# M22 — Deterministic paper trading

M22 adds a paper-order simulator for the agreed intraday long-option workflow. It consumes an immutable M21 market-feed capture, requires a valid M19 strategy certificate, and invokes the M18 risk policy immediately before every simulated entry. It never calls a Zerodha order endpoint.

Zerodha's production [order API](https://kite.trade/docs/connect/v3/orders/) can create real exchange orders. M22 intentionally has no HTTP client, route, credential, request type, or adapter for that API. Zerodha also documents a [no-real-money sandbox](https://kite.trade/docs/connect/v3/sandbox/), but M22 remains a local deterministic simulator so the same inputs always produce the same evidence.

## Apply the migration

```powershell
dotnet run --project src/Trading.Api -- database-update
```

This creates `dbo.PaperTradingSessions`. Startup never changes schema. The SSMS alternative is [sql/M22-Paper-Trading.sql](sql/M22-Paper-Trading.sql).

## Inputs and authorization

Before a session, you need:

1. an unexpired `ResearchQualified` M19 certificate whose artifact hash is valid and which explicitly allows paper testing;
2. a persisted M21 feed capture whose identity, tick count and SHA-256 are valid;
3. a reviewed paper-order input with `operatorApproved: true`.

For a session intended to count toward production M35 qualification, also supply the exact unexpired M34 artifact with `--qualified-strategy`. M22 verifies its SHA-256 and requires the M19 execution certificate to share the M34 strategy and research-run lineage. The resulting schema-v2 session binds both certificate chains. A legacy session without this bridge remains readable but cannot count toward production M35.

Copy [../samples/paper-trading.json](../samples/paper-trading.json) and replace the example IDs, instrument identity, prices and UTC timestamps. The certificate ID is available from `GET /api/certificates`; the feed capture ID is available from `GET /api/feed-captures`.

```powershell
New-Item -ItemType Directory -Force .\artifacts | Out-Null
dotnet run --project src/Trading.Api -- paper-trade `
  --certificate-id 00000000-0000-0000-0000-000000000000 `
  --feed-capture-id 00000000-0000-0000-0000-000000000000 `
  --qualified-strategy .\artifacts\qualified-strategy.json `
  --file .\samples\paper-trading.json `
  --output .\artifacts\paper-session-001.json
```

M22 supports long buys only. Quantity is never supplied by the operator: M18 calculates it from entry-to-stop risk and rounds down to complete lots. Every order uses the `strategyTesting` capital pool. Session cash cannot exceed the certificate's tested maximum capital, per-order risk is capped by both the certificate and current M18 policy, and maximum lots use the stricter certificate/order limit. The assumed slippage cannot be lower than the certificate's tested value.

## Deterministic fills and ledger

- Entry uses the first matching tick at or after submission. Its executable reference is best ask, followed by adverse buy slippage.
- Stop and target detection use the executable sell reference, best bid. The same bid is used for the exit fill before adverse sell slippage. LTP cannot trigger a stop or target when bid is available.
- If neither level triggers, the position exits at the last fresh tick no later than `plannedExitUtc`.
- Missing, stale, non-UTC, out-of-order or identity-mismatched market data rejects the order before a position is opened.
- Each completed trade records quantity, lots, entry/exit, reason, gross P&L, configured fees, net P&L, initial risk and the M18 decision hash.
- Portfolio state is rebuilt at each submission time. Open-position, averaging, aggregate risk, available cash, daily/weekly/monthly loss, daily trade count, consecutive loss, session-time and kill-switch gates therefore apply to later orders.

`quoteQualityPolicy` is explicit in the input and the schema-v2 result. The safe default, `requireBestBidAsk`, requires ask for entry and bid for every evaluated exit quote. Missing executable quotes reject the order. `allowLastPriceFallback` is available for lower-quality research captures; when selected, each completed trade records whether its entry or exit actually used `lastPriceFallback`. The selected policy, entry source and exit source are included in the immutable M22 artifact hash. Legacy result JSON remains readable and retains its original hash representation.

Fees are `2 × fixedFeePerFill + feeBasisPointsPerSide × (entry notional + exit notional) / 10,000`. Configure a conservative all-in value; M22 rejects a zero-fee assumption. It records the M19 certified cost-profile name but does not attempt to reverse-engineer that historical cost model from a name.

The output artifact binds certificate, capture, risk-policy and configuration hashes to the full session ledger and has its own SHA-256. SQL preserves the exact JSON plus summary values. `GET /api/paper-sessions` lists sessions and `GET /api/paper-sessions/{id}` returns the exact artifact. Re-running the same certificate, feed and configuration is rejected by a unique database key.

## Current boundary

This milestone is deterministic post-capture paper execution. It does not generate strategy signals, operate concurrently with a live socket, model partial fills or queue position, reconcile a broker account, or place sandbox/production orders. A later event-driven paper runner can use the same engine after durable account-state and disconnect/recovery behavior are designed. Live execution must remain a separate explicit milestone with M18 immediately in front of each broker request.
