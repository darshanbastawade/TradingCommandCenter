# M38.2 — Durable one-time M37 authorization consumption

M38.2 makes each M37 direct authorization usable at most once. The prepared M23 live order is persisted first, then one authorization action is atomically reserved in SQL, and only then can M23 call `PlaceLimitBuyAsync`.

`ControlledAutomationAuthorizations` is an insert-only consumption ledger. The automation decision ID is its primary key; authorization SHA-256, action ID, and related live-order ID are independently unique. A successful insert records one consumed action, first/last consumption UTC, the exact strategy/action identity, expiry, and related prepared order. Competing inserts have exactly one winner. No code path refunds or deletes a reservation.

Apply the EF migration explicitly:

```powershell
dotnet run --project src/Trading.Api -- database-update
```

Startup never changes the schema. For SSMS, use [M38.2-Durable-Automation-Authorization.sql](sql/M38.2-Durable-Automation-Authorization.sql), which is idempotent for the table, indexes, constraints, and migration-history row.

If the authorization is expired, malformed, already present, races with another process, or violates a unique identity, M23 fails before broker submission. If broker submission throws or times out after reservation, the authorization remains consumed and the prepared order remains available for manual reconciliation. Retrying with the same authorization is forbidden.

Semi-live never reads or writes the authorization-consumption store. M38.2 adds no scheduler, autonomous loop, AI input, Azure resource, or startup migration.
