# M31 — Robustness Suite

M31 adds a deterministic, seed-bound robustness artifact for a verified M25 `native-csharp` run with the `authoritative` role. It analyzes preserved trade evidence and never changes the source run. The suite covers Monte Carlo trade sequencing, bootstrap resampling, additional slippage, increased recorded costs, modeled entry latency, and randomly missed trades.

## Run the suite

Create an authoritative run with M25, then execute:

```powershell
dotnet run --project src/Trading.Api -- run-robustness-suite `
  --run .\artifacts\backtest-run.native.json `
  --output .\artifacts\robustness-suite.json
```

The command verifies the complete source result hash and capital ledger, requires at least one closed trade, refuses non-native or non-authoritative evidence, and will not overwrite an existing artifact. Output is written atomically and sealed with its own SHA-256.

Use `--settings .\artifacts\robustness-settings.json` to override the defaults:

```json
{
  "seed": 31031,
  "iterations": 2000,
  "ruinEquityFraction": 0.80,
  "additionalSlippageBasisPointsPerSide": [0, 5, 10, 20],
  "costMultipliers": [1, 1.25, 1.5, 2],
  "entryDelaySeconds": [0, 5, 15, 30],
  "entryDelayPenaltyBasisPointsPerSecond": 0.02,
  "missedTradeProbabilities": [0, 0.05, 0.10]
}
```

The seed drives an internal SplitMix64 generator implemented in the C# module, so simulation results do not depend on the runtime's `System.Random` implementation. The suite allows 100–100,000 iterations, at most 100,000 source trades, and at most 100 unique scenarios in each family. Every family must include its unchanged baseline (`0` slippage, `1×` cost, `0` delay and `0` missed-trade probability). Simulated trade observations are capped at 100 million per invocation.

## Calculations

### Monte Carlo

Each iteration shuffles all realized net trade P&Ls without replacement. Total P&L is therefore unchanged; the distribution measures ordering risk through maximum closed-trade drawdown, maximum consecutive losses, and probability that equity reaches the configured ruin threshold. It does not invent new trades or estimate the probability of the observed edge.

### Bootstrap

Each iteration samples the same number of trades with replacement from the realized net P&Ls. The artifact records 5th, median and 95th percentile net P&L, 95th percentile maximum drawdown and losing streak, probability of loss, probability of ruin, and median sampled trade count. This is an empirical trade bootstrap; it assumes sampled trades are exchangeable and does not preserve volatility regimes or serial dependence.

### Slippage stress

Each configured value is **additional** adverse slippage per side. The cash penalty for a trade is:

```text
(entry price + exit price) × quantity × additional bps / 10,000
```

The original run's slippage is already embedded in its prices. Scenario `0` is the unchanged baseline.

### Cost stress

Recorded costs are multiplied by each configured factor. The added cash penalty is:

```text
recorded costs × (multiplier − 1)
```

If the source run recorded zero costs, every multiplier has zero effect. That is evidence that a cost-bearing native run is needed, rather than evidence of cost robustness.

### Entry-delay stress

OHLCV run evidence cannot reconstruct prices five or fifteen seconds after a signal. M31 therefore uses a transparent latency-cost model instead of claiming tick-level replay:

```text
entry price × quantity × delay seconds × penalty bps per second / 10,000
```

The default penalty is `0.02` bp per second. This is a declared modeling assumption, not an observed delayed fill. When tick or quote replay becomes available, that data-aware analysis should replace this proxy.

### Missed-trade simulation

For every configured probability, each iteration independently drops each realized trade with that probability while preserving the order of retained trades. The same distribution fields as bootstrap are reported. Probability `0` is the unchanged baseline. This shows sensitivity to random execution omissions; it does not model systematic broker failures or signal-dependent misses.

## Evidence and scope

The artifact binds the source engine/version, source result hash, specification hash, declared dataset hash, consumed market-data hash, seed, settings, all summaries, and artifact SHA-256. Drawdown is calculated only after closed trades because `BacktestRun` has no intratrade equity curve. Ruin means equity reached or fell below `initial capital × ruinEquityFraction`; the default threshold is 80% of starting capital.

M31 produces evidence and no qualification verdict. It does not update ranking, issue a strategy certificate, call Azure OpenAI, place a broker order, change live gates, add a SQL table, or prove future profitability. M32 can define certificate gates after the team decides which M31 thresholds are acceptable.
