# M7 — Deterministic performance metrics

M7 turns an M5/M6 `BacktestResult` into a reproducible performance report. The calculator consumes the completed trade ledger, the observed candle sessions and an explicit exchange time zone. It does not query SQL Server or mutate a backtest.

## Trade metrics

All profit and loss metrics use completed trades. Costs are already included in net P&L.

```text
gross trading P&L = sum(pre-cost trade P&L)
net P&L = gross trading P&L - total costs
win rate = winning trades / total trades
average win = sum(positive net P&L) / winning trades
average loss = absolute(sum(negative net P&L)) / losing trades
payoff ratio = average win / average loss
net profit factor = sum(positive net P&L) / absolute(sum(negative net P&L))
expectancy per trade = net P&L / total trades
net R = trade net P&L / (absolute(entry - stop) × quantity)
recovery factor = net P&L / maximum closed-equity drawdown
```

Breakeven trades interrupt both winning and losing streaks. A ratio is `null` when its denominator does not exist or is zero; the implementation does not manufacture infinity. `AverageLoss` and `TotalNetLosses` are reported as positive magnitudes.

## Equity and drawdown conventions

The daily curve has one point for every exchange-local date represented by the supplied candles, including dates with no trade. Each daily return is realized P&L divided by that day's starting capital. This prevents inactive observed sessions from disappearing from risk-adjusted results.

Maximum drawdown scans `CapitalAfterTrade` after every completed trade, so a loss and recovery on the same day still records the closed-equity decline. Peak and trough dates use the supplied exchange time zone. The separate daily curve reports end-of-session drawdown. Neither calculation sees open-position movement, maximum adverse excursion or intrabar mark-to-market equity.

The calculator validates the ledger before calculating metrics: trade arithmetic and capital must reconcile, trades must be chronological, every exit must belong to an observed candle session, and candles must be chronological and share one instrument and timeframe.

## Annualized metrics

The default is 252 observed trading sessions per year. `PerformanceMetricSettings` makes that value, the periodic risk-free return and the periodic minimum acceptable return explicit.

```text
annualized return = (final capital / initial capital)^(periods per year / observed periods) - 1
annualized Sharpe = mean(period return - periodic risk-free return)
                    / sample standard deviation(period returns)
                    × sqrt(periods per year)
annualized Sortino = mean(period return - periodic minimum acceptable return)
                     / sqrt(mean(min(period return - minimum acceptable return, 0)^2))
                     × sqrt(periods per year)
```

Sharpe uses sample standard deviation. Sortino uses target downside deviation across all observed periods. Annualized metrics are `double?`; they are `null` for insufficient or unusable inputs, zero volatility, no downside deviation, nonpositive capital paths or non-finite annualization.

Annualized figures from a short backtest are mechanically valid but statistically unstable. The square-root-of-time scaling also assumes return behavior close enough to independent, identically distributed observations; serial correlation can materially distort it. M8 should add out-of-sample and walk-forward validation before metrics influence strategy qualification.

Method references: William Sharpe's [The Sharpe Ratio](https://www.web.stanford.edu/~wfsharpe/art/art1.htm), Andrew Lo's [The Statistics of Sharpe Ratios](https://alo.mit.edu/publications/page/18/), and the CME Research & Product Development paper [Sortino: A Sharper Ratio](https://www.cmegroup.com/education/files/rr-sortino-a-sharper-ratio.pdf).

## Scope

M7 adds no database table, migration, package, Azure resource, AI call, option selection or live execution path. Metrics remain research evidence and do not authorize a trade.

## Validation

```powershell
dotnet build TradingCommandCenter.sln --no-restore
dotnet test TradingCommandCenter.sln --no-build
```

Fixtures cover exact trade arithmetic, risk-adjusted returns, zero-trade sessions, same-session loss and recovery, empty results, invalid settings, inconsistent capital, missing sessions and instrument mismatch.
