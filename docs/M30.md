# M30 — Cross-engine trade comparison

M30 compares two saved M25 `BacktestRun` files: `native-csharp` with the `authoritative` role and `lean` with the `independentValidation` role. It verifies both result hashes and ledgers, then requires identical sealed specification, declared dataset hash, consumed market-data hash and initial capital. A mismatched experiment is rejected before trade matching. M30 does not run either engine.

```powershell
dotnet run --project src/Trading.Api -- compare-backtest-runs `
  --native .\artifacts\backtest-run.native.json `
  --lean .\artifacts\backtest-run.lean.json `
  --output .\artifacts\cross-engine-comparison.json
```

The matcher pairs trades only when strategy, instrument and direction agree. It reserves exact entry-time matches first, then selects the nearest unused entry within a five-minute window, breaking entry-time ties by exit-time distance. Every missing native/LEAN trade and every matched pair appears in the artifact. It reports matched-trade rate, entry/exit timestamp match rates, maximum entry/exit price deviations in basis points, net P&L deviation, and maximum closed-trade drawdown deviation. Timestamp rates are measured over matched pairs; matched-trade rate uses the larger engine trade count. P&L percentage deviation divides the absolute difference by the larger of ₹1 and the two absolute P&L values. Drawdown uses capital after each closed trade, so it does not claim to measure intratrade equity drawdown.

The default verdict requires all trades to match, exact entry/exit timestamps, no structural difference in quantity, signal time, stop, target, exit reason or costs, price deviations no greater than 1 bp, net P&L deviation no greater than 1%, and closed-trade drawdown deviation no greater than 0.5 percentage points. Two empty runs receive `noTrades`, never `pass`. A `pass` is agreement under this comparison policy; it is not strategy qualification or live-trading authorization.

You can provide a policy file with `--policy .\artifacts\comparison-policy.json`:

```json
{
  "entryMatchWindowSeconds": 300,
  "timestampToleranceSeconds": 0,
  "priceToleranceBasisPoints": 1,
  "minimumMatchedTradeRate": 1,
  "maximumNetPnlDeviationPercent": 1,
  "maximumDrawdownDeviationPercentagePoints": 0.5
}
```

The output records the policy, both engine versions and result hashes, every pair and difference, summary metrics, verdict, and its own SHA-256. The command refuses to overwrite an existing artifact. Exit code `0` means `pass`; `4` means `divergent` or `noTrades` (the artifact is still written); `2` means invalid input. Review and version the policy before using a relaxed tolerance in research decisions.

M30 adds no SQL migration, broker call, certificate gate or Azure resource. A real cross-engine result still requires an independently implemented and configured LEAN algorithm as described in [M29.md](M29.md). The adapter fixture tests do not establish actual LEAN strategy agreement.
