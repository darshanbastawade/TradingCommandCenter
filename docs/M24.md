# M24 — Universal Backtest Specification

M24 defines the immutable, engine-neutral input contract that future native, LEAN and vectorbt adapters will share. It does not run a backtest and gives no external engine execution or trading authority.

## Contract

The version-1 specification captures all inputs that materially affect reproducibility:

- strategy identity and a case-stable decimal parameter map; strategy-specific times use a documented numeric representation such as minute-of-day;
- instrument ID, exchange symbol, asset class, currency, lot size and tick size;
- a UTC half-open data range, timeframe, exchange time zone, calendar, source/version and dataset SHA-256;
- initial capital, risk per trade, maximum capital and maximum lots;
- reward/risk, slippage, cost profile, session exit and explicit signal/fill/ambiguous-bar/end-of-data policies.

The C# contract is in `Trading.Application.Backtesting`, an inward-facing module that does not depend on the native backtester. The portable JSON contract is [schemas/backtest-specification-v1.schema.json](schemas/backtest-specification-v1.schema.json).

## Normalize and seal a specification

Copy [../samples/backtest-specification.json](../samples/backtest-specification.json), replace its placeholder instrument and dataset identity, and keep all timestamps in UTC with `Z`.

```powershell
New-Item -ItemType Directory -Force .\artifacts | Out-Null
dotnet run --project src/Trading.Api -- seal-backtest-spec `
  --file .\samples\backtest-specification.json `
  --output .\artifacts\backtest-specification.sealed.json
```

The command validates the complete document, rejects unknown or duplicate JSON properties, rejects integer enum values, normalizes strings and parameter ordering, and writes a new document containing `specificationSha256`. Existing output files are never overwritten.

The hash covers canonical JSON for the normalized specification. It excludes file formatting and parameter insertion order, while any semantic change—including dataset identity, risk, costs, fill policy or parameter value—changes the hash.

`GET /api/backtest-specification` reports the active schema version and supported policy names without requiring SQL Server.

## Supported v1 semantics

- `ohlcvBars` requires `nextObservedBarOpen` entry fills.
- `observedOptionQuotes` requires `observedAsk` entry fills.
- signals use completed bars;
- ambiguous OHLC stop/target bars use stop-first handling;
- end-of-data positions close on the last observed bar;
- supported timeframes are 1, 3, 5, 15, 30, 60 and 1440 minutes.

The JSON Schema documents structure and basic ranges. The C# validator is authoritative for relational rules such as `fromUtc < toUtc`, capital boundaries, available Windows time-zone IDs, case-colliding parameter names and market-data/fill-policy compatibility.

## Milestone boundary

M24 does not replace the existing native settings yet, persist specifications, invoke vectorbt or LEAN, or define a common engine interface. M25 will add the engine abstraction and a native adapter; that adapter will translate this specification into the existing audited native settings while preserving the specification hash in its run evidence.
