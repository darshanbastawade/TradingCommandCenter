# M37 — Controlled Automation

M37 evaluates one bounded action against the complete M34 → M35 → M36 evidence chain. It verifies all three artifacts and their hashes and identities, then applies the automation kill switch, mode opt-ins, reconciliation freshness, per-run and daily action limits, and the daily loss limit.

Create an intent:

```json
{
  "actionId": "00000000-0000-0000-0000-000000000001",
  "mode": "observe",
  "actionReference": "signal-2026-09-23-001",
  "requestedActions": 1,
  "completedActionsToday": 0,
  "realizedLossToday": 0,
  "operatorApproved": false,
  "confirmation": null
}
```

```powershell
dotnet run --project src/Trading.Api -- evaluate-automation `
  --qualified-strategy .\artifacts\qualified-strategy.json `
  --paper-qualification .\artifacts\paper-qualification.json `
  --reconciliation .\artifacts\live-reconciliation.json `
  --file .\samples\controlled-automation.json `
  --output .\artifacts\controlled-automation-decision.json
```

Committed settings are fail-closed: automation is disabled, semi-live and direct-live are disabled, and the independent M37 kill switch is engaged. Direct eligibility additionally requires `operatorApproved: true` and the exact confirmation `ALLOW-CONTROLLED-AUTOMATION`. A permitted decision expires after 30 seconds and authorizes at most one action.

M37 deliberately emits an eligibility artifact and does not submit to Zerodha (`brokerSubmissionPerformed` is always false). A live entry still goes through M23, including its own M18 evaluation, current broker reads, shared kill switch, two direct-order opt-ins and `PLACE-LIVE-ORDER` confirmation. This preserves two independent control layers while the project still lacks an automated exit lifecycle and a broker event ingestion service. Do not treat `directSubmissionEligible` as evidence that an order was sent or filled.

M37 adds no scheduler, background worker, database migration, Azure resource or unattended broker loop.
