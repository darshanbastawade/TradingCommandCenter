# M37 — Controlled Automation

M37 evaluates one bounded action against the complete M34 → M35 → M36 evidence chain. It verifies all three artifacts and their hashes and identities, then applies the automation kill switch, mode opt-ins, reconciliation freshness, per-run and daily action limits, and the daily loss limit. Since M38.3, daily action and realized P&L inputs come only from durable internal state.

Create an intent:

```json
{
  "actionId": "00000000-0000-0000-0000-000000000001",
  "mode": "observe",
  "actionReference": "signal-2026-09-23-001",
  "requestedActions": 1,
  "operatorApproved": false,
  "confirmation": null
}
```

```powershell
dotnet run --project src/Trading.Api -- evaluate-automation `
  --qualified-strategy .\artifacts\qualified-strategy.json `
  --paper-qualification .\artifacts\paper-qualification.json `
  --reconciliation .\artifacts\live-reconciliation.json `
  --file .\samples\controlled-automation.json `
  --output .\artifacts\controlled-automation-decision.json
```

Committed settings are fail-closed: automation is disabled, semi-live and direct-live are disabled, and the independent M37 kill switch is engaged. Direct eligibility additionally requires `operatorApproved: true` and the exact confirmation `ALLOW-CONTROLLED-AUTOMATION`. A permitted decision expires after 30 seconds and authorizes at most one action. Caller-supplied completed-action or P&L properties are ignored and have no authority.

The state provider uses the India exchange-local trading date. It combines consumed M37 authorizations, submitted direct M23 orders, and the latest authoritative reconciled execution-state record. Missing or stale state, unresolved broker submissions, and active broker positions block eligibility. Realized loss is `max(0, -reconciled realized P&L)`; a profitable day never expands the configured action or risk limits.

For `DirectLive`, M37 also requires an M36 schema-v2 artifact whose source mode is `authoritativeBroker`. A `reconcile-live-file` diagnostic artifact cannot produce direct eligibility.

M37 deliberately emits an eligibility artifact and does not submit to Zerodha (`brokerSubmissionPerformed` is always false). Since M38.1, direct M23 submission requires this artifact through `--automation-authorization`, plus its own M18 evaluation, current broker reads, shared kill switch, two direct-order opt-ins and `PLACE-LIVE-ORDER` confirmation. This preserves two independent control layers while the project still lacks an automated exit lifecycle and a broker event ingestion service. Do not treat `directSubmissionEligible` as evidence that an order was sent or filled.

M37 adds no scheduler, background worker, Azure resource or unattended broker loop. M38.3 adds the `ReconciledExecutionStates` table through an explicit migration; application startup still never changes the database.
