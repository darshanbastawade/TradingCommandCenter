# M2 — Historical candle CSV importer

M2 adds local commands to register instruments, validate canonical candle CSV files, and import completed bars into the M1 database. It reuses the existing schema; no new migration or NuGet package is needed. There are no broker or AI calls, and no new HTTP write endpoints.

## Try a dry run in VS Code

Run from the folder containing TradingCommandCenter.sln:

```powershell
dotnet restore TradingCommandCenter.sln --locked-mode
dotnet build TradingCommandCenter.sln --no-restore
dotnet test TradingCommandCenter.sln --no-build
$csv = (Resolve-Path samples/candles.synthetic.csv).Path
dotnet run --project src/Trading.Api --no-build -- import-candles --file "$csv" --instrument-id 11111111-1111-1111-1111-111111111111 --timeframe 5 --dry-run
```

The sample is invented data, not a real instrument or market history. The dry run works without SQL Server or credentials. It returns `validated-file-only`, three rows, UTC time bounds, a SHA-256 checksum of the original file bytes, and a gap count. It does not check the instrument master, tick size or database duplicates, and writes nothing.

## Register an instrument and import

First finish [Market database setup](Market-setup.md). The API uses the same connection configuration for these commands as it does for the web host. Use the existing environment variable or Development User Secrets. The commands do not apply migrations automatically.

For the synthetic sample only:

```powershell
dotnet run --project src/Trading.Api --no-build -- add-instrument --instrument-id 11111111-1111-1111-1111-111111111111 --exchange TEST --symbol SYNTHETIC --name "Synthetic demonstration" --lot-size 1 --tick-size 0.05
dotnet run --project src/Trading.Api --no-build -- import-candles --file "$csv" --instrument-id 11111111-1111-1111-1111-111111111111 --timeframe 5
```

The first command registers an instrument once. Repeating it rejects the duplicate rather than changing metadata. For real data, use a new stable GUID and verified instrument metadata; do not reuse the synthetic example. Imported OHLC prices must be exact multiples of the registered tick size. Lot size does not constrain candle volume.

Each command exits after completion; it does not start the web server. Existing `dotnet run --project src/Trading.Api` still starts the website at http://localhost:5080. The status endpoint now reports M2.

## CSV contract

The exact header is:

```csv
timestamp,open,high,low,close,volume,openInterest
2026-09-01T09:15:00+05:30,100.00,102.00,99.00,101.00,1000,
2026-09-01T09:20:00+05:30,101.00,103.00,100.50,102.50,1200,
```

- UTF-8, optional UTF-8 BOM, LF or CRLF. Seven unquoted fields. This is a strict numeric interchange format, not a general spreadsheet-export parser; quoted fields, embedded commas, blank rows and changed headers are rejected.
- Timestamp is the bar-open time: `yyyy-MM-ddTHH:mm:ssZ` or `yyyy-MM-ddTHH:mm:ss±HH:mm`. An explicit offset is required. Timestamp seconds must be zero. The importer converts each instant to UTC before sorting/duplicate checks.
- One instrument and timeframe per file; timeframe is supplied as minutes: 1, 3, 5, 15, 30, 60 or 1440. Rows must already be strictly chronological. Duplicate UTC instants, reversed order and internally overlapping bars are errors. No automatic sorting or deduplication occurs.
- Positive OHLC prices with at most four decimal places, dot decimal separator, no thousands separators or scientific notation. High/low must enclose open/close. Volume and open interest are nonnegative whole numbers fitting a signed 64-bit integer. Blank open interest means unavailable; zero means a measured zero.
- Bars must be completed at validation time, using `open time + timeframe duration <= UTC now`. Daily bars conservatively require a full 24 hours after their open timestamp; this is not an exchange close-time calculation.
- Up to 10,000 data rows and 4 MiB per file; each line is limited to 1,024 characters. Split larger datasets into non-overlapping files. Each file is atomic; there is no transaction across multiple files.
- Gaps larger than one timeframe are counted as intervals, not as missing-bar totals. Gaps may represent overnight closures, holidays or missing data. No bars are manufactured or filled. Exchange calendars, session boundaries and exchange-specific bar grids are not validated in M2. A successful import does not certify dataset completeness or market authenticity.

## Failure and duplicate policy

The whole file is validated before writing anything. The instrument and tick size are then checked, and the requested UTC keys are checked against existing data using paged queries. An existing key rejects the entire file, even if its values are identical. The database primary key remains the final guard if concurrent imports race. There is no overwrite, correction, skip-duplicates or upsert mode.

The persistence operation is a single atomic SaveChanges call. A constraint failure rolls back the import. If a connection interruption or cancellation occurs during commit, its outcome may be uncertain: inspect the stored range before retrying. Keep the original CSV and the JSON summary as research provenance; M2 does not yet store file checksums or import audit records in SQL.

Command exit codes:

| Code | Meaning |
| --- | --- |
| 0 | File validated, instrument registered, or import completed |
| 2 | Invalid arguments, input file, missing instrument, tick-size mismatch or preflight duplicate |
| 3 | Persistence/configuration failure, including a concurrent duplicate rejected by SQL |
| 130 | Cancelled |

Input errors include the CSV line number where applicable. Command output contains a JSON success summary; errors go to stderr. Credentials and database exception details are not printed. Unknown/duplicate options are rejected.

## Verification and remaining setup

Unit tests exercise UTC offset handling, culture-independent numbers, row limits, malformed OHLCV, ordering, gaps and incomplete bars. Relational integration tests cover valid imports, repeat-import rejection, no writes after validation failure, tick-size checks, and command registration/import paths. Dry-run command testing needs no database.

Database tests use SQLite in memory, and the existing SQL Server migration/model checks still run. SQL Server is installed and configured for Market. Live readiness, instrument registration, a three-candle import, stored values, and duplicate rejection were verified successfully. The temporary synthetic rows were removed afterward, leaving the two trading tables empty.

The next logical milestone is deterministic indicators over stored candles. CSV normalization for specific data vendors, exchange calendars and broker download adapters remain separate work.
