# M28 — Native Candidate Verification

M28 closes the research screening loop by replaying selected M27 candidates through the M25 engine whose role is `authoritative`.

```powershell
dotnet run --project src/Trading.Api -- verify-backtest-candidates `
  --sweep-id YOUR-SWEEP-GUID `
  --top 10 `
  --output ./artifacts/native-candidate-verification.json
```

For every selected candidate, the command re-verifies the stored sealed specification, specification hash and declared dataset hash before invoking native C#. A successful result must pass the M25 run codec and match the candidate and sweep identities. The complete native run JSON, result hash, net P&L and trade count are stored. Expected specification or engine failures are retained as `NativeFailed` evidence rather than being silently discarded.

Candidate updates, the sweep completion marker and `NativeCandidateVerificationRuns` artifact are committed in one SQL transaction. A unique sweep index prevents a second verification run from overwriting the first. Native verification establishes reproducible engine execution only; it does not establish profitability, out-of-sample validity, qualification, certificate eligibility or live-trading authority.

M28 adds no broker operation, Azure resource or AI request. M18 risk gates and M19 certificates remain unchanged.
