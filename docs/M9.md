# M9 — Deterministic reporting and local UI

M9 converts a completed backtest and its observed candles into a stable report document, then introduces the first usable command-center interface. Reporting consumes M7 calculations; it does not recalculate trading decisions or round values back into the research engine.

## Report document

`BacktestReportBuilder.Build` validates the ledger through `BacktestMetricsCalculator` and returns schema version 1 with:

- strategy IDs, instrument, timeframe and observed session range;
- the complete M7 performance summary and daily realized equity curve;
- total net R, median net R and maximum drawdown measured on cumulative trade R;
- average and median trade duration in minutes;
- target, stop-loss, session-exit and end-of-data exit rates;
- monthly, yearly, entry-weekday and entry-time-bucket breakdowns.

Net R uses trade net P&L after modeled costs:

```text
net R = net P&L / (absolute(entry - stop) × quantity)
```

Maximum drawdown R scans cumulative closed-trade R from a zero starting peak. Monthly and yearly results assign a trade to its exchange-local exit date because that is when P&L becomes realized. Weekday and time-bucket results use the exchange-local entry time because they describe entry behavior.

Each breakdown reports trades, wins, losses, breakeven trades, net P&L, win rate and average net R. Undefined statistics are `null`, including all trade-only outcomes for an empty ledger.

## Default time buckets

| Label | Start inclusive | End exclusive |
| --- | ---: | ---: |
| Open | 09:15 | 09:45 |
| Morning | 09:45 | 11:00 |
| Midday | 11:00 | 13:30 |
| Afternoon | 13:30 | 15:30 |

Custom buckets must have unique case-insensitive labels, positive ranges and no overlap. Trades outside the configured ranges appear in an explicit `Outside configured buckets` row instead of disappearing.

## JSON export

`BacktestReportJson.Serialize` emits camel-case JSON and includes `schemaVersion`. Serialization uses strict numeric handling, so `NaN` and infinity cannot enter report artifacts. M7 already represents undefined ratios as JSON `null`.

The schema version protects future readers when fields or conventions change. A later persistence milestone can store the serialized document without coupling the UI to mutable calculation classes.

## Local UI

The API now maps static web assets from the `Trading.Web` Razor class library. The application provides:

- `/` — milestone overview, architecture boundary and navigation;
- `/reports` — report dashboard and available report sections;
- `/api/reports` — schema-versioned catalog contract.

There is no stored backtest-run entity yet, so the catalog returns an empty collection and the dashboard explicitly says `No saved reports yet`. M9 does not display fabricated performance. The report builder and JSON exporter are ready for a later backtest orchestration/persistence workflow to supply genuine results.

## Scope

M9 adds no database table, migration, package, Azure resource, AI call, broker connection or order path. A report is research evidence and does not qualify a strategy or authorize a trade.

## Validation

```powershell
dotnet build TradingCommandCenter.sln --no-restore
dotnet test TradingCommandCenter.sln --no-build
dotnet run --project src/Trading.Api --launch-profile http
```

Fixtures verify exact R and duration statistics, month and time-bucket boundaries, uncovered trades, empty reports, bucket validation, versioned strict JSON, report routes and the M9 status contract. The overview and report pages were also rendered in a browser to confirm that Razor class-library styling is served by the API host.
