# M5 — Deterministic completed-candle backtesting

M5 turns strategy candidates into a reproducible research trade ledger. The engine operates on one ordered instrument/timeframe candle series and one deterministic strategy. It does not place, route or simulate broker orders.

## Default settings

| Setting | Default |
| --- | ---: |
| Initial capital | ₹100,000 |
| Quantity | 1 unit |
| Entry and exit slippage | 0 basis points per side |
| Variable transaction cost | 0 basis points of turnover per side |
| Fixed transaction cost | ₹0 per side |
| Session exit | 15:25 exchange local time |

Defaults are intentionally neutral so individual effects can be tested exactly. Research runs should provide realistic slippage and costs for the traded instrument. Quantity is fixed in M5; the Risk module will own capital-based position sizing in a later milestone.

## Fill and position rules

1. A candidate formed from a completed candle can enter only at the next observed candle's open. The signal candle's close is never used as an achievable fill.
2. The following candle must be in the same exchange-local session and must open before the configured session-exit time.
3. Adverse entry slippage is applied to the next open. Stop and target are then recalculated from the executed entry using the candidate's risk-per-unit and reward/risk multiple.
4. Only one position can be open. Candidates formed while a position remains open are recorded as ignored.
5. The entry candle can hit a stop or target after its open. For later candles, a gap through a stop exits at the adverse open. A favorable gap through a target fills at the target, which is the conservative limit-order assumption.
6. If both stop and target lie within one OHLC candle, the stop wins because bar data cannot establish the intrabar sequence.
7. At the configured session-exit bar, an open position exits at that bar's open. If the dataset jumps to a new session without that bar, the position exits at the previous observed candle's close.
8. A remaining position exits at the final candle's close with reason `EndOfData`.

Invalid candidates are rejected before simulation. Candidates that lack a following bar, would cross a session, arrive while a position is open, or produce non-positive levels after a gap are retained as ignored-candidate diagnostics.

## P&L and costs

Slippage is adverse in both directions: it raises a long entry and short exit, and lowers a short entry and long exit. Gross P&L uses slipped execution prices and fixed quantity. Costs contain two fixed per-side charges plus the configured basis-point charge on entry and exit turnover. Net P&L updates capital only when a trade closes.

Every completed trade records strategy, instrument, direction, signal/entry/exit bar-open UTC identifiers, quantity, executed prices, stop, target, exit reason, gross P&L, costs, net P&L and capital after trade. For close-based session or end-of-data exits, the exit identifier still names the candle because OHLCV data has no separate close timestamp. The result also exposes final capital and basic winning/losing trade counts.

## Scope and limitations

M5 uses completed OHLCV bars, so stop-first handling is an explicit conservative convention rather than knowledge of the intrabar path. It does not model partial fills, liquidity, bid/ask spread, exchange price bands, tick-size rounding, margin, option contract selection, dynamic sizing, taxes by Indian instrument type, corporate actions or portfolio concurrency.

M5 adds no NuGet package, database migration or table. Results remain in memory. M6 should add realistic Indian-market cost profiles and risk-based position sizing before advanced metrics and out-of-sample validation.

## Validation

```powershell
dotnet build TradingCommandCenter.sln --no-restore
dotnet test TradingCommandCenter.sln --no-build
```

Fixtures verify next-bar entry, long and short targets, ambiguous stop-first behavior, stop gaps, session and end-of-data exits, adverse slippage, fixed and turnover costs, capital arithmetic, ignored candidates, invalid input and deterministic module boundaries.
