# M38.4 — Selection-resistant paper qualification

M38.4 replaces the production M35 session manifest with a durable-store query. M34 `QualifiedAtUtc` starts the observation window; the operator supplies only an inclusive UTC cutoff. Every M22 session linked to the exact M34 qualification in that window is discovered and evaluated.

New production paper sessions use M22 schema v2 and persist the M34 qualification ID/SHA-256, the M32 certificate ID/SHA-256 carried by M34, and the M34 qualification start UTC.

M22 still applies its M19 certificate and M18 controls. When creating schema-v2 evidence, it also verifies the M34 artifact and requires the M19 certificate to share its strategy and research-run lineage. This is an explicit bridge; old M22 sessions are never relabeled as M34-reviewed sessions.

M35 verifies the complete stored artifact and persisted summary, operator approval, exact lineage, and one India exchange-local date. Duplicate or altered evidence is excluded, recorded with a reason, and blocks qualification. Schema-v2 M35 evidence records the full observation window and every included session ID/hash. M36 now requires this schema, so manifest-derived schema-v1 evidence cannot reach production reconciliation or automation.

M38.4 adds no broker call, AI execution input, scheduler, autonomous loop, or Azure resource.
