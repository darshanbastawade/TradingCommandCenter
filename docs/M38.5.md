# M38.5 — Authoritative live reconciliation

M38.5 preserves the deterministic `LiveReconciliationEngine` and adds production orchestration around it. The production `reconcile-live` command reads expected state through `IInternalTradingLedgerReader` and fetches current account identity, margins, positions, and day orders through `ILiveBrokerReconciliationClient`.

The Zerodha adapter calls the profile endpoint and requires its `user_id` to match `Zerodha:UserId`. It then fetches equity margins, net positions, and orders. Any HTTP, response, identity, timestamp, or status-mapping failure stops reconciliation without producing an eligible artifact.

Internal state is a schema-v1 immutable `InternalTradingLedgerArtifact` stored in `InternalTradingLedgerSnapshots`. It contains expected available cash, reconciled realized P&L, positions, order/fill state, unresolved-event count, source-event SHA-256, broker identity, and a monotonic revision. The reader verifies the artifact against its SQL identity and SHA-256. Production orchestration also verifies every direct M23 row and submitted artifact/receipt and requires a one-to-one mapping to ledger order events.

Run authoritative reconciliation:

```powershell
dotnet run --project src/Trading.Api -- reconcile-live `
  --paper-qualification .\artifacts\paper-qualification.json `
  --output .\artifacts\live-reconciliation.json
```

The resulting schema-v2 artifact records `authoritativeBroker`, broker provider/account, broker snapshot SHA-256, internal ledger SHA-256, and internal revision. A zero-difference result writes a fresh `ReconciledExecutionState` for M38.3. M37 requires this authoritative source for `DirectLive`.

The former JSON comparison remains available only as:

```powershell
dotnet run --project src/Trading.Api -- reconcile-live-file `
  --paper-qualification .\artifacts\paper-qualification.json `
  --file .\samples\live-reconciliation.json `
  --output .\artifacts\diagnostic-reconciliation.json
```

A diagnostic artifact records `diagnosticFile`, remains ineligible for controlled automation, and cannot authorize direct live submission even when its compared values match.

Apply migration `20260923060024_M38AuthoritativeReconciliation` explicitly with `database-update`, or use [M38.5-Authoritative-Reconciliation.sql](sql/M38.5-Authoritative-Reconciliation.sql). Startup never migrates the database.

This milestone supplies the immutable ledger contract and durable reader, but it does not invent fill events. A trusted order-event/fill ingestion path must persist fresh internal ledger artifacts before production reconciliation can pass. If none exists, or if it is stale, invalid, incomplete, or unresolved, M36 fails closed. No autonomous trading loop or broker order call was added.
