# M38.3 — Durable controlled-automation state

M38.3 removes completed-action counts and daily loss from the operator-controlled M37 intent. The intent now carries only the requested action identity, mode, reference, quantity, operator approval, and confirmation. Extra legacy JSON properties cannot influence the decision.

`IControlledAutomationStateProvider` builds a deterministic point-in-time snapshot from durable internal records. For the current India exchange-local date it reads:

- consumed M37 direct authorizations;
- submitted M23 direct orders;
- reconciled realized P&L;
- unresolved broker submissions; and
- active/open broker positions.

M37 schema-v2 artifacts record the state timestamp, exchange date, action counts, reconciled P&L, unresolved/position counts, and a canonical SHA-256 over the durable evidence. Direct M23 authorization accepts schema v2, so a legacy M37 artifact without state evidence remains readable but cannot authorize a new direct order.

The daily action gate uses the greater of consumed authorizations and submitted actions, then adds the requested action. Daily loss is `max(0, -realized P&L)`. Positive realized P&L never increases the configured action count or risk allowance. Missing, unavailable, future-dated, stale, or wrong-date state fails closed. Any unresolved broker submission or active broker position also blocks controlled automation.

Trading dates use `India Standard Time`, including the UTC date boundary at 18:30. Realized P&L must come from actual reconciled results. Proposals and unrealized estimates are not accepted as daily P&L evidence.

Apply the EF migration explicitly:

```powershell
dotnet run --project src/Trading.Api -- database-update
```

Startup never changes the schema. For SSMS, use [M38.3-Durable-Execution-State.sql](sql/M38.3-Durable-Execution-State.sql). The script is idempotent for the table, constraints, indexes, and migration-history row.

Since M38.5, a successful broker-backed M36 reconciliation writes the authoritative row. That path itself requires a fresh verified internal ledger snapshot. Without both sources, `evaluate-automation` returns an `execution-state-unavailable` block and direct eligibility remains closed. Tests use deterministic persisted fixtures; they are not evidence of a live broker reconciliation.

M38.3 adds no scheduler, autonomous trading loop, Azure resource, AI execution input, or broker call.
