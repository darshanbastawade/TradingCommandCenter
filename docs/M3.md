# M3 — Deterministic indicator engine

M3 adds pure indicator calculations in `Trading.Strategies/Indicators`. The engine consumes validated Candle objects and returns timestamp-aligned results for EMA, session VWAP, Wilder ATR, Wilder ADX/+DI/-DI, and rolling average volume. It makes no database, network, broker, AI, clock, or configuration calls.

## Default indicator set

`IndicatorEngine.Calculate` combines the series into one `IndicatorSnapshot` per input candle. Defaults are:

- Fast EMA: 20 bars
- Slow EMA: 50 bars
- ATR: 14 bars
- ADX/+DI/-DI: 14 bars
- Average volume: 20 bars
- VWAP: resets at each calendar date in the explicitly supplied exchange timezone

The fast EMA period must be smaller than the slow period. All periods are configurable and validated. Callers must supply the exchange timezone; for NSE/BSE on Windows, use `TimeZoneInfo.FindSystemTimeZoneById("India Standard Time")`. Passing the timezone keeps session behavior independent of the computer's local timezone.

## Calculation conventions

- Every output series has exactly the same length and UTC timestamps as the input. Values that do not yet have enough history are `null`, never zero.
- EMA is seeded with the simple average of the first full period, then uses multiplier `2 / (period + 1)`.
- ATR uses true range and Wilder smoothing. Its first value appears at index `period - 1` using the first period true ranges.
- +DI and -DI first appear at index `period`. ADX is the average of the first period DX values and first appears at index `2 * period - 1`; later values use Wilder smoothing. Flat prices produce zero DI/DX/ADX rather than division errors.
- VWAP uses typical price `(high + low + close) / 3`, weighted by volume. It resets when the exchange-local calendar date changes. It remains `null` until a session has positive cumulative volume; zero-volume bars do not change an established VWAP.
- Rolling average volume requires a complete window and uses decimal arithmetic, avoiding integer truncation.
- Results retain decimal calculation precision and are not rounded for display. UI/reporting code must choose presentation rounding without feeding rounded values back into strategy decisions.

## Input contract and gaps

Candles must be from exactly one instrument and one timeframe, in strictly increasing UTC order. Mixed instruments, mixed timeframes, duplicate timestamps, reversed order, invalid periods, and invalid fast/slow EMA relationships throw argument exceptions. Empty input returns empty output.

Time gaps are permitted because M2 preserves holidays, overnight closures, and missing bars. Indicators treat the next record as the next observed bar; no synthetic bars are inserted and periods count observations, not elapsed minutes. Before trusting a backtest, the dataset-quality layer must distinguish expected session gaps from missing intraday data. M3 does not yet implement an exchange calendar.

Session VWAP resets by exchange-local date, not by a configurable session-open timestamp. This matches normal NSE/BSE intraday data but does not cover overnight sessions. The initial bar of each date starts a new VWAP even if the data begins mid-session, so partial-session input produces a partial-session VWAP.

## Usage

```csharp
var india = TimeZoneInfo.FindSystemTimeZoneById("India Standard Time");
var snapshots = IndicatorEngine.Calculate(candles, india);

foreach (var point in snapshots.Where(point => point.Adx is not null))
{
    // Consume full-precision values in deterministic strategy rules.
}
```

No indicator values are stored in SQL in M3. Backtests will compute them from immutable candle evidence, which avoids stale derived columns and makes runs reproducible with an explicit parameter set. If performance later requires caching, cached results must include source-data identity, algorithm version, timezone, and every parameter.

## Verification and boundaries

StrategyValidationTests cover known EMA, volume-average, ATR, VWAP, +DI/-DI and ADX values; warm-up positions; UTC alignment; exchange-date resets; zero volume; flat prices; gaps; empty input; and invalid inputs. The full solution build and test suite remain the milestone gate.

M3 does not add a migration, API endpoint, UI chart, strategy signal, backtest, MACD, opening-range logic, swing classification, or dataset-completeness certification. The next milestone can define the strategy contract and implement the first hypothesis using these indicator snapshots.
