# M6 — Risk sizing and Indian-market costs

M6 replaces fixed research quantities with an optional deterministic position sizer and adds dated Zerodha/NSE transaction-cost profiles. Fixed quantity and zero costs remain the defaults so prior fixtures and neutral research runs stay reproducible.

## Risk-based position sizing

The sizer accepts allowed rupee risk, executed entry, stop, exchange lot size, maximum capital per trade and an optional maximum-lot cap.

```text
risk per unit = absolute(entry - stop)
units by risk = floor(allowed risk / risk per unit)
units by capital = floor(maximum capital / entry)
lots = floor(min(units by risk, units by capital) / lot size)
quantity = lots × lot size
```

Every division rounds down. The engine recalculates stop and target after entry slippage, then sizes from that executed entry. If the result cannot fund one complete lot, the candidate is recorded with `InsufficientRiskOrCapital`; no trade is created. The result reports quantity, lots, unit risk, total risk, capital required and unused risk.

The capital formula assumes a cash-funded instrument or purchased option premium. It does not estimate futures or short-option margin. Lot size must come from dated instrument reference data because exchange lot sizes can change.

## Dated Zerodha/NSE profiles

Rates were checked on September 14, 2026 against Zerodha's charges schedule, Zerodha's STT guidance and NSE circular NSE/FA/73061. Each profile has an effective date in its ID so later rate changes require a new profile instead of silently changing historical results.

| Component | NSE equity intraday | NSE equity options premium |
| --- | ---: | ---: |
| Profile effective date | 2026-03-01 | 2026-04-01 |
| Brokerage per executed order | min(₹20, 0.03% turnover) | ₹20 |
| STT | 0.025% sell side | 0.15% sell-side premium |
| Exchange + IPFT | 0.00307% each side | 0.03553% premium each side |
| SEBI charge | ₹10/crore each side | ₹10/crore premium each side |
| Stamp duty | 0.003% buy side | 0.003% buy-side premium |
| GST | 18% of brokerage + exchange/IPFT + SEBI | same |

STT is rounded to the nearest rupee with ₹0.50 rounding upward, matching the broker's published rule. Other components retain decimal precision so the research ledger remains auditable. Actual contract notes may aggregate and round charges across multiple orders or a trading day.

The options profile operates on premium turnover. Use it only when entry and exit prices are actual option premiums. The current VWAP + EMA hypothesis evaluates underlying candles; applying options-premium costs to those underlying prices would be invalid until an option-contract selection and premium-data layer exists. Exercise and assignment STT are outside M6.

Official references: [Zerodha charges](https://zerodha.com/charges), [Zerodha STT calculation and April 2026 rates](https://support.zerodha.com/category/account-opening/resident-individual/ri-charges/articles/how-is-the-securities-transaction-tax-stt-calculated), and [NSE transaction-charge circular NSE/FA/73061](https://nsearchives.nseindia.com/content/circulars/FA73061.pdf).

## Backtest integration

`BacktestSettings.RiskBasedSizing` enables calculated quantity. `BacktestSettings.CostModel` selects a named component-level model. A completed trade stores brokerage, STT, exchange/IPFT, SEBI, stamp duty, GST, other costs and the total. M5's generic fixed and turnover-basis-point inputs remain available and are added under `Other` when used.

M6 does not enforce daily, weekly or monthly loss stops, consecutive-loss rules, portfolio exposure, margin, liquidity, partial fills, tick rounding, option selection or live execution. M7 should add the performance and drawdown metrics engine before out-of-sample and walk-forward validation.
