# M34 — Qualified Strategy Pipeline

M34 creates the review envelope between research evidence and the later paper-qualification stage. It accepts only a verified, unexpired M32 `evidenceQualified` certificate and a verified M33 analysis bound to that exact certificate.

```powershell
dotnet run --project src/Trading.Api -- qualify-strategy `
  --certificate .\artifacts\strategy-certificate-v2.json `
  --analysis .\artifacts\astra-research-analysis-v2.json `
  --operator-approval-reference REVIEW-2026-001 `
  --output .\artifacts\qualified-strategy.json
```

The operator approval reference is a 3–128 character audit reference, such as a review ticket. Do not put credentials or secrets in it. Qualification must happen after certificate issuance and before certificate expiry. The default policy allows research ranks 1–2 only.

The artifact binds certificate and analysis IDs and hashes, research run, strategy, rank, expiry, analyst recommendation, operator reference and the qualification policy. The ID is stable for the same evidence, policy and operator reference; the time-stamped payload receives its own SHA-256.

Deterministic M32 evidence decides eligibility. M33 cannot change that decision: even `reject` is recorded as advisory and requires the operator to decide whether to proceed, while an M32 rejection can never be overridden by Astra or the operator reference. The resulting state is `eligibleForPaperQualification`. It does not itself prove paper performance, start an M22 session, authorize semi-live/direct-live trading, or place an order. Those flags remain false.

M34 uses portable local artifacts and adds no database migration. M35 should define durable paper-performance gates and decide how a qualified-strategy artifact advances into a paper authorization. Existing M19 V1 certificates and M22/M23 flows remain readable; M34 does not silently reinterpret them as V2 evidence.
