# M29 — LEAN external validation adapter

M29 adds `Trading.ExternalValidation`, an `IBacktestEngine` with ID `lean` and role `independentValidation`. It accepts the same sealed M24 specification as native C#, reads the declared SQL candle range, and writes an isolated schema-v2 request and CSV package under `Lean:DataDirectory/tcc-lean/<runId>`. It invokes `external/lean/TradingCommandCenterLean` through `lean backtest` with an immutable image digest and `tccRunId`. The LEAN project does not reference or load native strategy code.

The algorithm independently implements `vwap-ema-trend-breakout-v1`, including EMA, Wilder ATR/ADX/DI, session VWAP, previous average volume, signal gates, next-bar entry, risk sizing, stop-first OHLC exits, session/end exits and slippage. It submits its independently planned fills through LEAN so official `TotalPerformance.ClosedTrades` is produced, then writes `evidence.json`. The adapter reconciles every official closed trade, seals the portable M25 run, and records the official result SHA-256, image digest, algorithm source revision, strategy implementation version, `tccRunId`, request hash and candle-file hash.

Adapter version 2 accepts only OHLCV equity/equity-index specifications for `vwap-ema-trend-breakout-v1`, its exact parameter set, and the `none` cost profile. The other four strategies, observed option quotes and broker-cost profiles fail closed until separately implemented and validated.

Configure the API on a machine with the LEAN CLI, Docker, a local LEAN project, and a CLI data directory mounted into its container. For example, set the following in ignored `appsettings.Local.json` or environment variables:

```json
{
  "Lean": {
    "CliExecutable": "lean",
    "ProjectDirectory": "C:\\path\\to\\TradingCommandCenter\\external\\lean\\TradingCommandCenterLean",
    "DataDirectory": "C:\\path\\to\\your\\lean-data",
    "Image": "quantconnect/lean@sha256:<64-hex-digest>",
    "TimeoutSeconds": 1800
  }
}
```

After sealing an M24 specification whose instrument and candles exist in SQL Server:

```powershell
dotnet run --project src/Trading.Api -- run-backtest-spec `
  --engine lean `
  --file .\artifacts\backtest-specification.sealed.json `
  --output .\artifacts\backtest-run.lean.json
```

The image must be supplied by digest; mutable tags are rejected. `tcc-strategy-manifest.json` binds `lean-vwap-ema-trend-breakout-v1` to the normalized SHA-256 of `main.py`. A source change invalidates the project until the manifest is deliberately renewed.

This development machine had neither Docker nor the LEAN CLI installed, so no official-runtime result is claimed in repository verification. The standard-library parity harness ran the independent algorithm against the same deterministic fixture as native C# and passed the unchanged strict M30 policy. M32 rejects comparisons lacking official-runtime provenance. LEAN cannot authorize a live trade.
