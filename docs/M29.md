# M29 — LEAN external validation adapter

M29 adds `Trading.ExternalValidation`, an `IBacktestEngine` with ID `lean` and role `independentValidation`. It accepts the same sealed M24 specification as native C#, reads the declared SQL candle range, and writes an isolated request and CSV package under `Lean:DataDirectory/tcc-lean/<runId>`. It then invokes a configured local LEAN CLI project through `lean backtest` with an explicit image tag or digest and `tccRunId` parameter. Use an immutable image digest for reproducible validation. The adapter does not reuse the native strategy or fill engine.

The LEAN project is a separately maintained implementation. To produce valid evidence, its algorithm must load `tcc-lean/<tccRunId>/request.json` and `candles.csv` from the CLI data folder, independently apply the requested strategy and execution rules, and write `evidence.json` in that run directory. The evidence must be a canonical M25 `BacktestRun` with engine ID `lean`, role `independentValidation`, the sealed specification hash, declared dataset hash, consumed row hash, engine version `1:<configured-image>`, and the LEAN trades. The adapter requires LEAN's official output `<backtestId>.json` and compares every portable closed trade's times, prices, quantity, gross P&L and fees with its `closedTrades` records. Missing, inconsistent or oversized evidence fails closed. Each input package is removed after the invocation.

Version 1 accepts only OHLCV equity/equity-index specifications using the five known strategy IDs, an exact parameter set, and the `none` cost profile. Observed option quotes and broker-cost profiles are rejected. This deliberately does not imply that any of the five strategies has a validated LEAN implementation: supply and verify an independent LEAN algorithm before treating a result as external validation. No LEAN algorithm, CLI installation, Docker image, SQL migration, broker operation, or cloud resource is bundled with this milestone.

Configure the API on a machine with the LEAN CLI, Docker, a local LEAN project, and a CLI data directory mounted into its container. For example, set the following in ignored `appsettings.Local.json` or environment variables:

```json
{
  "Lean": {
    "CliExecutable": "lean",
    "ProjectDirectory": "C:\\path\\to\\your\\lean-project",
    "DataDirectory": "C:\\path\\to\\your\\lean-data",
    "Image": "quantconnect/lean:<tested-version>",
    "TimeoutSeconds": 1800
  }
}
```

After sealing an M24 specification whose instrument and candles exist in SQL Server:

```powershell
dotnet run --project src/Trading.Api -- run-backtest-spec `
  --engine lean `
  --file .\artifacts\backtest-specification.sealed.json `
  --output .\artifacts\backtest-run.lean.json
```

`GET /api/backtest-engines` lists the registration even when LEAN is unconfigured. The adapter tests use a fixture process runner to check packaging, identity and official-trade reconciliation. They do not claim an actual LEAN backtest passed. Before relying on LEAN findings, run the configured project on a known fixture and inspect its official output, portable evidence, and the engine/version recorded in the result. Cross-engine trade comparison and tolerance policy remain M30 work. LEAN cannot authorize a strategy certificate or live trade.
