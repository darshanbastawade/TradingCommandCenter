# M4 — Strategy contract and first hypothesis

M4 introduces a deterministic strategy contract and the first research hypothesis: `vwap-ema-trend-breakout-v1`. A strategy receives an ordered candle series plus the exchange time zone and returns zero or more auditable candidate signals. A candidate is not an order and has no execution authority.

## Default hypothesis

| Parameter | Default |
| --- | ---: |
| Fast / slow EMA | 20 / 50 |
| ATR / ADX period | 14 / 14 |
| Rolling volume period | 20 bars |
| Breakout lookback | 3 bars |
| Minimum ADX | 25 |
| Volume multiplier | 1.2× |
| Stop distance | 1× ATR |
| Reward/risk target | 3R |
| Entry window | 09:30 inclusive to 11:30 exclusive, exchange local time |

Every indicator must be warmed up before a signal is eligible. The current completed candle must be inside the entry window and must satisfy all of these rules:

- Long: fast EMA is above slow EMA, close is above session VWAP, +DI is above -DI, and close exceeds the highest high of the previous breakout bars.
- Short: fast EMA is below slow EMA, close is below session VWAP, -DI is above +DI, and close is below the lowest low of the previous breakout bars.
- Both directions: ADX meets the threshold and current volume meets the multiplier against the **previous candle's** rolling volume average.

The previous volume average excludes the breakout candle, so its own volume cannot dilute the comparison. Breakout bars must belong to the same exchange-local session. Gaps are treated as gaps between observed bars; no candles are invented.

## Candidate output

Entry is the completed signal candle's close. The initial stop is one configured ATR multiple from entry and the target is the configured reward/risk multiple. These are hypothesis levels for research. M4 does not model whether a real order could fill at that close, tick-size rounding, gaps, slippage, brokerage, taxes, option selection or position size.

Each candidate records its strategy ID, instrument, UTC bar time, direction, entry, stop, target, risk per unit and the EMA, VWAP, ATR, ADX, directional-index, volume and breakout evidence that caused it. The strategy can emit candidates on consecutive candles; the backtest engine will own position state and entry policy.

## Determinism and scope

The evaluator calculates each candle only from that candle and earlier candles. Tests confirm that adding a future candle does not alter an existing signal. Parameters are immutable and validated at construction. Invalid periods, thresholds, multipliers and entry windows fail immediately.

M4 adds no NuGet package, database table or migration. It does not select an options contract, execute trades, rank strategies or call Azure OpenAI. M5 will add the deterministic backtest engine and define fill/exit behavior around these candidates.

## Validation

From the repository root:

```powershell
dotnet build TradingCommandCenter.sln --no-restore
dotnet test TradingCommandCenter.sln --no-build
```

Strategy validation covers the stable contract, exact long and short levels, 3R arithmetic, volume rejection, entry-window boundary, session reset, warm-up and flat-market behavior, invalid parameters, and future-bar invariance.
