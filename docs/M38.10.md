# M38.10 — CI and verification closure

M38.10 makes the repository verify itself on every push and pull request. The single required check is the `CI / verify` job in `.github/workflows/ci.yml`, which is suitable for branch protection.

## Required CI check

The `verify` job runs on GitHub-hosted Ubuntu and:

1. checks out the repository;
2. reads the exact SDK version from `global.json`, installs it, and verifies selection;
3. installs Python 3.13 and every exact dependency in `workers/vectorbt/requirements.lock.txt`;
4. compiles and smoke-tests the real vectorbt worker;
5. restores the solution in locked mode;
6. builds the full Release solution without restoring;
7. runs the five native C#/Python parity fixtures explicitly;
8. runs the complete .NET test suite without rebuilding; and
9. retains TRX results as a GitHub Actions artifact.

The check supplies only fail-closed test configuration. It has no Azure OpenAI or Zerodha credentials, makes no paid AI call or broker call, and cannot submit a live order.

## Manual LEAN validation

`.github/workflows/lean-validation.yml` is an optional `workflow_dispatch` workflow. It targets a deliberately labelled self-hosted validation runner with Docker and the LEAN CLI already installed. The operator must provide:

- an M29 `tccRunId` whose immutable `request.json` and `candles.csv` are already staged in the validation data directory;
- the absolute LEAN data root containing `tcc-lean/<tccRunId>`; and
- an immutable LEAN image reference containing `@sha256:<64 hex characters>`.

The workflow invokes the official LEAN runtime and uploads its raw result plus `evidence.json`. It does not run on pushes or pull requests, has no broker or AI credentials, and forces all live-feed/order gates closed. A workflow run is genuine external evidence only when the selected self-hosted runner and image execute successfully; the presence of the workflow file itself is not a completed LEAN validation.

## Branch protection

After this workflow has run at least once on GitHub, configure the repository's protected branch to require the check named `CI / verify`. The manual LEAN workflow should remain optional until its dedicated runtime and deterministic validation data are available.
