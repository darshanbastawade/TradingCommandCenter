# M36 — Live Reconciliation

M36 compares the command center's expected cash, positions, and submitted M23 orders with a detailed broker snapshot. It requires a verified, unexpired and qualified M35 artifact. Cash tolerance is explicit; positions are grouped by token, exchange, symbol and product; orders are matched by broker order ID and checked for request identity, instrument, status, quantity, filled quantity and average fill price.

The input shape is:

```json
{
  "asOfUtc": "2026-09-23T06:00:00Z",
  "expectedAvailableCash": 30000,
  "brokerAvailableCash": 30000,
  "cashTolerance": 1,
  "expectedPositions": [],
  "brokerPositions": [],
  "liveOrderArtifactFiles": [],
  "internalOrders": [],
  "brokerOrders": []
}
```

`asOfUtc` must be refreshed immediately before the command; the committed maximum age is 30 seconds. Each non-empty `internalOrders` entry must match the immutable identity and ordered quantity in a supplied M23 artifact. This lets an imported local ledger advance an order from submitted to partially filled, filled, cancelled or rejected without altering the original artifact. Broker snapshots must come from a trusted export/adapter; M36 cannot prove the provenance of a manually authored snapshot.

```powershell
dotnet run --project src/Trading.Api -- reconcile-live `
  --paper-qualification .\artifacts\paper-qualification.json `
  --file .\artifacts\live-reconciliation-input.json `
  --output .\artifacts\live-reconciliation.json
```

Any difference produces a sealed `divergent` artifact and exit code 4. Only a zero-discrepancy result is eligible for M37. M36 performs no database mutation and no broker order action.
