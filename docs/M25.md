# M25 — Backtest Engine Abstraction

M25 introduces a small engine boundary around the existing deterministic backtester. Native C# remains the authoritative calculator. A later LEAN adapter can provide independent validation and a later vectorbt adapter can support research exploration without changing the M24 input contract.

## Contracts and authority

`IBacktestEngine` accepts a sealed M24 specification and returns a portable `BacktestRun`. Each engine declares an ID, version and role:

- `authoritative` — the result used by the command center for native research decisions;
- `independentValidation` — a separate implementation used to compare results;
- `researchExploration` — a fast exploratory implementation that cannot replace authoritative evidence.

The run records both the declared M24 dataset hash and a SHA-256 fingerprint of the market rows actually consumed. It also preserves the specification hash, engine identity, capital summary, trades, ignored candidates and a final canonical result hash. Validation checks summary counts, P&L totals, trade chronology and the capital ledger before evidence is sealed or accepted.

## Native adapter v1

The `native-csharp` version-1 adapter translates the universal specification into the existing audited `BacktestSettings` and five native strategy implementations. It strictly requires the complete parameter set for the selected strategy and rejects unknown parameters.

Version 1 supports:

- OHLCV bar specifications for `equity` and `equityIndex` instruments;
- completed-bar signals and next-observed-bar-open entry fills;
- no costs or the dated Zerodha NSE equity-intraday cost profile;
- whole-lot risk sizing, slippage, session closure and the M5 deterministic fill rules.

Observed option-quote specifications remain on the dedicated M17 engine and are rejected by this adapter. The abstraction does not silently translate those semantics into OHLCV behavior.

## Run a sealed specification

First create the sealed input described in [M24.md](M24.md). Its instrument must already exist in SQL Server and its requested candle range must contain data.

```powershell
New-Item -ItemType Directory -Force .\artifacts | Out-Null
dotnet run --project src/Trading.Api -- run-backtest-spec `
  --engine native-csharp `
  --file .\artifacts\backtest-specification.sealed.json `
  --output .\artifacts\backtest-run.native.json
```

The command verifies the sealed specification before resolving the requested engine, refuses an existing output file, verifies the returned run evidence and writes atomically. `GET /api/backtest-engines` lists registered engine metadata without opening a database connection.

## Milestone boundary

M25 adds no SQL table, migration, NuGet package, Azure resource, broker call or AI request. It does not implement LEAN or vectorbt, compare engines, certify cross-engine tolerances, persist portable runs or change the live-trading gates. Those require explicit later milestones.
