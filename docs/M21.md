# M21 — Zerodha paper/live feed

M21 adds a normalized market-feed boundary with three sources: deterministic paper replay, Zerodha sandbox WebSocket, and explicitly enabled Zerodha production WebSocket. It receives quotes and persists bounded, immutable capture artifacts. It has no order endpoint and cannot place, modify, or cancel an order.

The implementation follows Zerodha's official [WebSocket streaming protocol](https://kite.trade/docs/connect/v3/websocket/): binary frames are parsed as big-endian packet containers, 1-byte heartbeats are ignored, and `ltp`, `quote`, and `full` modes are supported. Zerodha permits up to 3,000 instruments per connection and three WebSocket connections per API key; M21 enforces the 3,000-subscription limit for one capture. The [instrument documentation](https://kite.trade/docs/connect/v3/market-quotes/) warns that derivative instrument tokens may be reused after expiry, so every configured token must also include its exchange and trading symbol.

## Apply the database migration

```powershell
dotnet run --project src/Trading.Api -- database-update
```

This creates `dbo.MarketFeedCaptures`. Startup never updates schema. The SSMS alternative is [sql/M21-Zerodha-Market-Feeds.sql](sql/M21-Zerodha-Market-Feeds.sql).

## Run deterministic paper replay

The replay source reads one normalized JSON tick per line, requires chronological UTC receive timestamps, and runs without delays or network access. The committed sample has three full-mode NIFTY ticks:

```powershell
New-Item -ItemType Directory -Force .\artifacts | Out-Null
dotnet run --project src/Trading.Api -- capture-market-feed `
  --source paper `
  --mode full `
  --subscriptions .\samples\zerodha-subscriptions.json `
  --replay-file .\samples\market-feed-replay.ndjson `
  --max-ticks 3 `
  --output .\artifacts\paper-feed-001.json
```

The subscription file is an array of `instrumentToken`, `exchange`, `tradingSymbol`, and `priceDivisor`. Indian equity and derivative prices normally use divisor 100. Set the correct divisor from the instrument segment for every subscription.

## Configure Zerodha locally

Put credentials in the API project's User Secrets. Never add them to appsettings, source, command lines, logs, screenshots, or capture artifacts.

```powershell
dotnet user-secrets set "Zerodha:ApiKey" "YOUR-API-KEY" --project src/Trading.Api
dotnet user-secrets set "Zerodha:AccessToken" "YOUR-ACCESS-TOKEN" --project src/Trading.Api
dotnet user-secrets set "Zerodha:UserId" "YOUR-USER-ID" --project src/Trading.Api
```

The `UserId` is needed for the sandbox endpoint. Zerodha's [login documentation](https://kite.trade/docs/connect/v3/user/) states that access tokens expire at 6 AM the following day, so refresh the secret after completing the official interactive login flow. M21 does not automate login or store a request token.

For sandbox capture:

```powershell
dotnet run --project src/Trading.Api -- capture-market-feed `
  --source sandbox --mode full `
  --subscriptions .\samples\zerodha-subscriptions.json `
  --max-ticks 100 `
  --output .\artifacts\sandbox-feed-001.json
```

Zerodha documents its test WebSocket endpoint in the [Kite Connect sandbox guide](https://kite.trade/docs/connect/v3/sandbox/). A production capture additionally requires the local opt-in below; the committed default is `false`.

```powershell
dotnet user-secrets set "Zerodha:AllowLiveFeed" "true" --project src/Trading.Api
dotnet run --project src/Trading.Api -- capture-market-feed `
  --source live --mode full `
  --subscriptions .\samples\zerodha-subscriptions.json `
  --max-ticks 100 `
  --output .\artifacts\live-feed-001.json
```

Press Ctrl+C to cancel a capture that is waiting for ticks. A cancelled or empty capture is not written or persisted. Existing output files are never overwritten. Completed captures are available at `GET /api/feed-captures`; `GET /api/feed-captures/{id}` returns the exact stored artifact.

## Evidence and boundaries

Each artifact includes source, mode, subscription identities, normalized ticks and a SHA-256 computed before the hash field is populated. The same JSON is written atomically to disk and stored in SQL. This gives later paper-execution work a reviewable input without treating network data as trusted strategy evidence.

M21 does not aggregate ticks into candles, renew Zerodha sessions, download an instrument master, recover gaps after disconnect, reconnect automatically, maintain an account ledger, simulate orders, or send live orders. Those need explicit later milestones and the M18 hard risk policy must remain in front of every future order path.
