# M35 — Paper Qualification

Production M35 is SQL-backed and selection-bias resistant. The operator declares only an evaluation cutoff. M35 uses the M34 `QualifiedAtUtc` as the observation start and queries every durable M22 session linked to that exact M34 qualification whose `CreatedAtUtc` lies in the inclusive window.

Create the cutoff input. Replace the example with a UTC instant after M34 qualification, before its expiry, and no later than the current time:

```json
{
  "qualificationCutoffUtc": "2026-09-23T10:00:00Z"
}
```

Run:

```powershell
dotnet run --project src/Trading.Api -- qualify-paper `
  --qualified-strategy .\artifacts\qualified-strategy.json `
  --file .\samples\paper-qualification.json `
  --output .\artifacts\paper-qualification.json
```

There is no production session manifest. M35 loads all matching rows through `IPaperQualificationSessionQuery`; an operator cannot omit a losing session. Each accepted row must contain a SHA-256-valid schema-v2 M22 artifact, operator approval, one India exchange-local trading date, exact persisted summary values, and the M34 qualification/certificate identity and hash. Strategy-name equality alone is insufficient.

Discovered evidence that is duplicated, altered, unapproved, multi-date, or lineage-mismatched is recorded by session ID and reason and forces rejection. The schema-v2 result records observation start/cutoff, first and last accepted session times, discovered and accepted counts, rejected evidence, and each included session ID/hash. Ordering and identity generation are deterministic for the same cutoff and durable state.

Committed gates require 10 sessions across at least 5 India-market trading dates, 30 filled trades, a 60% profitable-session rate, no more than 25% rejected orders, and positive aggregate net P&L. A qualified artifact enables M36 reconciliation only; semi-live and direct-live flags remain false.

Legacy schema-v1 M35 artifacts remain hash-verifiable and readable, but M36 refuses them. Only a durable-store schema-v2 qualification can enter the production M36/M37 chain.

Apply the lineage migration explicitly with `database-update`, or use [sql/M38.4-Paper-Qualification-Lineage.sql](sql/M38.4-Paper-Qualification-Lineage.sql). Startup never migrates the database. M35 makes no broker or AI call.
