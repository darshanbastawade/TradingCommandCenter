# M35 — Paper Qualification

M35 promotes an M34 qualified strategy only after its real M22 paper sessions pass durable performance gates. It reads portable artifacts, recomputes every SHA-256, verifies each paper session's embedded strategy and operator approval, rejects duplicate sessions, and writes a new hash-bound artifact.

Create a manifest whose paths are relative to the manifest file (absolute paths also work):

```json
{
  "sessionFiles": [
    "../artifacts/paper-session-01.json",
    "../artifacts/paper-session-02.json"
  ]
}
```

Run:

```powershell
dotnet run --project src/Trading.Api -- qualify-paper `
  --qualified-strategy .\artifacts\qualified-strategy.json `
  --file .\samples\paper-qualification.json `
  --output .\artifacts\paper-qualification.json
```

Committed gates require 10 sessions across at least 5 India-market trading dates, 30 filled trades, a 60% profitable-session rate, no more than 25% rejected orders, and positive aggregate net P&L. Each M22 session must contain orders from one trading date. Failure still produces a sealed `rejected` artifact and returns exit code 4. A qualified artifact enables M36 reconciliation only; its semi-live and direct-live authorization flags remain false.

M35 adds no database migration and does not call a broker.
